## Проблема
LLM-агент может использовать локальный инструменты, веб-поиск, MCP, размышления и внешние инструменты для работы. При этом в его запусках возникают повторяющиеся ошибки: неверный выбор инструмента, некорректные аргументы, лишние вызовы, неверная интерпретация наблюдений и преждевременное завершение.

Ручное исправление инструкций требует времени и может ухудшить работу на других задачах. Необходимо исследовать, какая обратная связь позволяет автоматически улучшать конфигурацию агента, насколько улучшения переносятся на новые проблемы, задачи и каких затрат требует поиск.

## Цель и исследовательский вопрос

**Цель:** разработать и экспериментально оценить систему, которая анализирует завершённые запуски агента, выявляет повторяющиеся ошибки, предлагает изменения конфигурации и проверяет кандидатов на отдельном наборе задач.

**Исследовательский вопрос:** позволяет ли обратная связь, сформированная из проверяемых событий среды, эффективнее улучшать агента при ограниченном бюджете, чем свободный текстовый анализ его траекторий?

## Экспериментальная среда

В качестве экспериментальной среды рассматривается SREGym - платформа для тестирования LLM-агентов на задачах эксплуатации и восстановления IT-инфраструктуры.

В проекте используется облегчённый набор задач SREGym-Lite. Он позволяет воспроизводить различные неисправности в приложениях, развёрнутых в Kubernetes, и проверять способность агента находить и устранять их причины.

Среди рассматриваемых проблем: ошибки сетевого взаимодействия, ограничения ресурсов, неправильные настройки сервисов, проблемы с доступом и сбои при развёртывании приложений.

Среда будет использоваться для запуска базового агента, сбора траекторий его действий и последующей оценки оптимизированных конфигураций.

## Исследование данных (EDA)

На первом этапе проводится анализ сценариев отказов из SREGym-Lite.

Цель анализа: определить, какие типы неисправностей представлены в наборе задач, чем они отличаются, как могут проявляться и какие действия необходимы агенту для их диагностики и устранения.

Для каждого сценария рассматриваются:
- категория неисправности;
- причина и наблюдаемые симптомы;
- необходимые данные для диагностики;
- возможный способ устранения проблемы;
- ожидаемый результат работы агента.

## Каталог и классификация сценариев SREGym-Lite

После подготовки экспериментального стенда планируется дополнить разведочный анализ данными реальных запусков агента: успешностью решения задач, количеством вызовов инструментов, временем выполнения, расходом токенов и характерными ошибками.

Эти данные будут использованы для определения базового качества агента и выбора направлений оптимизации.

Основные критерии сравнения: успешность решения задач, затраты на выполнение и способность сохранять качество на ранее не использованных сценариях.
